# 메모리 작성 거버넌스

메모리 작성·수정·압축 전에 읽는 상세 정책의 정본이다. 저장소 탐색·읽기·현재 상태 대조는 [공통 규칙](../AGENTS.md)을 따른다.

- 요약과 이력에는 관련 계획 ID·버전과 코드 상태를 연결한다. 다른 역할의 세션에도 영향을 주는 결정·제약·위험은 현재 요약에 드러낸다.
- 로컬 진행 기록에는 관련 계획 ID·버전과 실제 변경 커밋 해시를 연결한다. 스쿼시 머지 등으로 최종 이력이 달라지면 확인한 최종 커밋이나 PR 링크를 추가하고 기존 구현·검토 기준은 보존한다. 간소 경로는 기존 결과 보고나 필요한 최소 기록에 해시를 남기며, 이를 위해 계획 ID나 별도 파일을 만들지 않는다.
- 중요한 결정·계획 변경·문제 해결만 이루어진 대화에서도 관련 이력과 요약을 갱신한다. 코드 구현이 있어야만 기록하는 것은 아니다.

### 간소 경로의 최소 기록

- 별도 계획 ID, progress 파일, 이력 파일을 형식적으로 생성하지 않는다. 단순히 끝난 변경은 결과 보고로 마칠 수 있다.
- 중요한 결정·문제 해결·검증 한계가 향후 작업에 영향을 주거나 세션 전환 시 재개할 내용이 있으면 current.md에 요구·변경 범위·코드 기준·검사·다음 행동을 짧게 기록한다. 상세 근거가 필요할 때만 memory/history에 원본을 남긴다. 계획이 없음을 명시하며 가짜 ID·revision을 만들지 않는다.
- 정식 경로로 전환하면 해당 계획에서 기존 변경과 기록을 연결한다.

### 현재 상태와 계획별 진행

- `current.md`에는 진행 중인 S/P/T, 구현 위치, 주요 결정·제약·미해결 위험, 다음 작업과 관련 기록 링크를 짧은 자연어 문장으로 유지한다. 무공백 압축이나 약어 나열보다 사람이 재개 지점을 이해할 수 있는 표현을 쓴다.
- `progress/<ID>.md`에는 해당 계획의 실제 구현 범위, 남은 작업, 대기·무효화 사유와 관련 원본 이력 링크를 기록한다.
- 진행은 T에서 기록하고 P는 하위 T를, S는 하위 P를 집계한다. 근거 없는 완료율 대신 실제 끝난 범위와 남은 범위를 보여준다.
- 상위 진행 요약에 상세 이력을 중복해서 쓰지 않는다. 하위 기록을 참조하며 갱신한다.
- 계획 변경으로 무효화되면 진행 기록에도 이를 표시한다. 이미 작성한 코드와 현재 계획에 부합하는 구현을 구분하며, 재검토 전의 작업을 유효한 완료로 집계하지 않는다.
- 구현 진행과 검증 결과를 혼동하지 않는다. 수용 조건별 검사 결과와 미확인 범위를 연결하고, 독립 검토와 실행 검증은 공통 규칙의 독립 검토 규칙을 따른다. 작업 유형별 세부 테스트 기준은 후속 논의에서 정한다.

### 원본 이력과 결정 기록

- `.harness/memory/history/`에는 실제 작업, 계획 변경, 결정 이유, 문제·해결 방법, 실패한 시도와 타협을 기록한다.
- 결정 기록에는 관련 계획·코드 상태, 결정 내용과 이유, 검토한 대안, 받아들인 타협, 남은 우려와 재검토 조건을 남긴다.
- 확인된 사실, 확정 결정, 미확정 제안과 가정을 구분한다. 요약 과정에서 제안을 결정으로 바꾸지 않는다.
- 상세 과정은 원본에 보존하고, 계획별 진행과 현재 요약에서 해당 원본으로 연결한다.
- 승인·대기는 기존 기록 한곳에 종류, 대상(계획 버전·코드·환경 등), 적용 범위, 현재 상태와 해소 근거, 남은 조건을 연결한다. 실행·재사용·구현·배포 승인과 시각 확인을 구분하고, 시각 확인을 실행 권한으로 해석하지 않는다. 이미 유효한 사용자 승인은 해당 범위에서 재사용하되 실제 도구의 거절을 승인 기록으로 우회하거나 해소된 것으로 표시하지 않는다. 계획의 `waiting_on`과 현재 요약에는 필요한 상태와 원본 참조만 둔다.

### 갱신과 컴팩트

- 의미 있는 구현 단위가 끝나면 원본 이력을 추가하고 관련 계획별 진행 및 현재 요약을 갱신한다. 매번 전체 이력을 다시 요약하지 않는다.
- 세션 종료·전환 시에는 작업이 미완료여도 마지막 작업 위치, 미해결 문제, 다음 시작점을 남긴다.
- `current.md`는 초기 기준으로 약 1~2화면 분량을 지향한다. 엄격한 줄 수 제한보다 새 세션이 현재 상황과 주의점·재개 지점을 파악할 수 있는지를 우선한다.
- 요약이 길어지거나 종료된 작업의 세부 내용이 누적되면 재압축한다. 해결된 문제와 과거 작업의 상세 내용은 하위 기록에 두고 링크로 연결한다.
- 압축 시 원본 이력을 삭제하지 않는다. 현재 제약, 미해결 위험, 중요한 타협, 다음 작업과 근거 링크는 유지한다.
- 기록을 갱신하는 에이전트 절차와 자동 기록·압축 기능의 구현을 구분한다. 자동화가 구현되었다고 가정하지 않는다.
