# 발전 계획

## 1. 기반 정리 — 완료

- 저장소 목적과 공통 규칙의 정본을 정한다.
- 회사 설정과 분리된 개인 GitHub 인증 및 커밋 작성자를 설정한다.
- 개인 원격 저장소에 연결하고 첫 커밋을 게시한다.

## 2. 작업 방식 수집

- 계획과 실행의 경계, 질문이 필요한 시점, 선호하는 결과 보고 방식을 정리한다.
- 테스트, 리뷰, 커밋, 배포의 기본 원칙을 논의한다.
- 실제 사례를 통해 규칙의 효과를 확인한다.

### 반영한 작업 선호

- 구현 전 계획을 문서화하고 사용자와 반복 검토한다.
- 복잡한 작업은 최상위 기획서 → 큰 틀의 계획서 → 상세 코드 작성 계획서로 나누며, 계층별 질문과 상하위 정합성을 유지한다.
- 계획 문서는 S / P / T와 프로젝트 내 고유 ID로 구분하며, 문서 내부의 상위 관계와 의존성에 따라 작업을 조율한다.
- 문서 끝의 미완결 사항과 불확실성을 사용자와 논의하며 문서를 갱신한다.
- 2026-10-20 검증·검토를 마친 변경 단위의 로컬 커밋과 푸시·PR의 명시적 지시 경계를 합의했다. 커밋 정책은 `rules/AGENTS.md`, 계획과 해시 연결은 메모리 작성 거버넌스를 따른다.

### 확정한 문서 식별 방식

S(Spec) / P(Plan) / T(Task), `[ID] 주제` 형식의 제목과 ID에 맞춘 파일명을 채택했다. 메타데이터는 `id`·`revision`·`parent`·`parent_revision`·`depends_on`·`waiting_on`이다. 상세 계획 규칙의 정본은 `rules/governance/planning.md`다. 번호는 실행 순서를 나타내지 않으며 의존성은 문서 내부에 적는다.

### 추가로 확정한 계획 운영

- 변경 영향에 따라 T, P→T, S→P→T를 선택한다. 작은 신규 기능은 새 개념·방향 결정이 없다면 S를 생략할 수 있다.
- P에서 기존 코드와 인터페이스·제약을 조사하고, T만 작성할 때도 직접 관련된 코드를 확인한다.
- 상위 방향 변경 시 연결된 하위 계획 전체를 무효화하고 위에서 아래로 재검토한다. 문서 삭제 대신 이전 판단을 보존하며 상위 버전 일치 여부를 실행 전에 확인한다.
- 순환 의존성은 금지하고 외부 대기는 최상단 메타데이터로 표시한다.
- 개인 계획·메모리는 대상 레포 `.harness/`에 두고 로컬 Git exclude로 제외한다. 기존 외부 저장소 방식을 대체하며 공동 레포의 공유 설정은 바꾸지 않는다.

### 계획 작성의 추가 논의 후보

아래는 점검 과정에서 발견한 보완 후보이며, 아직 공통 규칙으로 확정하지 않는다.

- 로컬 `.harness/` 초기화·Git 제외·경로 충돌 처리의 CLI 구현.
- 계획 문서 전체의 탐색 방식, 코드 브랜치·커밋 기준 정보의 필드명, worktree·복수 clone 연결 방식.
- T 하나에 담을 작업 범위의 기준.
- 이전 계획 버전과 무효화 이유의 구체적 보존 형식, 자동 관계 탐색·버전 검사 기능. 합의한 작업 메모리와의 구체적인 자동 연결 방식은 추후 설계한다.
- 로컬 계획·메모리의 백업·동기화와 회사/개인 보관 범위 분리.

### 확정한 작업 메모리 운영

- 프로젝트 단위 메모리를 coding·infra 등 순차 세션에서 공유한다.
- 레포 로컬 `.harness/`에 `plans/`, `memory/current.md`, `memory/progress/<ID>.md`, `memory/history/` 구조를 사용한다. `progress/`는 계획 원본이 아닌 실제 진행 요약이다.
- 현재 맥락 → 계획별 진행 → 원본 이력으로 연결하고 필요한 깊이까지 탐색한다. T 진행을 P·S에서 집계한다.
- 결정·계획 변경·문제·해결·타협의 원본을 보존하고 현재 제약과 위험을 요약에 노출한다.
- 구현 단위마다 상태를 갱신하고 세션 전환 때 재개 지점을 남긴다. 길어진 요약은 원본과 링크를 보존하며 재압축한다.
- 세션 시작 시 메모리의 기준 계획·코드 상태를 현재 상태와 대조한다. 불일치는 근거를 확인한 뒤 기록에 반영하고 확인 불가 사항은 불확실성으로 남긴다.
- 계획은 `rules/governance/planning.md`, 메모리 작성·갱신·압축은 `rules/governance/memory-writing.md`로 분리했다. 메모리 읽기·상태 대조·갱신 시점은 공통 지침에 유지한다.
- 중요한 결정·계획 변경·문제 해결만 이루어진 대화도 기록 대상이며, 실제 작성·수정·압축 전에 작성 거버넌스를 읽는다.

### 메모리의 후속 설계

- 원본 이력 파일의 명명 방식, 진행 상태의 공통 표기와 기록 템플릿.
- 구체적인 요약 길이 기준, 자동 갱신·집계·압축 구현, 이전 계획 버전 보존과의 연결.
- 세션 동시 실행과 기록 충돌 처리는 현재 합의한 순차 세션 범위를 넘어선 후속 과제다.

### 보류한 논의

- 수용 조건과 검사 방법·실제 결과·미확인 범위를 기존 계획·검토·진행 기록에서 연결하도록 구체화했다. 작업 유형별 세부 테스트 기준과 완료 판정 정책은 후속 논의로 남긴다.

### 확정한 독립 검토 운영

- 주 세션이 계획·구현·수정과 검토 호출을 조율한다. 구현자 전용 역할은 현재 만들지 않는다.
- 계획 검토는 사용자에게 계획을 제시하기 전, 결과 검토는 구현자의 검사·테스트 이후 새 에이전트 맥락에서 수행한다.
- 역할 정의는 `agents/plan-reviewer.md`, `agents/implementation-reviewer.md`에 둔다. 공통 호출·처리 규칙은 `rules/AGENTS.md`를 따른다.
- 검토자는 원본과 실행 근거를 확인하고 직접 수정하지 않는다. 주 세션이 지적 처리·재검토와 공유 메모리 반영을 담당한다.
- 독립 리뷰와 실행 테스트 및 사용자 승인을 구분한다. 미확인 범위와 실행 제약을 보고한다.
- 결과 검토자 하나에 CODE/RUN/ENV 모드를 적용한다. 검토 요청서로 범위·검사·환경·허용 행위를 정하고 실제 사용 경험에 따라 조정한다. 상세 정본은 결과 검토자 역할 파일이다.
- 검토 모드와 접근 권한을 분리하고 필요한 도구만 제공한다. 직접 실행과 주 세션이 전달한 원본 근거를 구분한다.

### 검토의 후속 설계

계획 검토자는 `.codex/agents/plan-reviewer.toml`과 개인 등록 링크로 연결했다. 상세 안내는 `docs/codex-plan-reviewer.md`를 따른다. 관계·리비전 검사는 필수이며 주 세션의 착수 직전 확인도 유지한다. 새 세션에서 등록 역할 발견·호출 확인은 별도로 필요하다.

- 결과 검토자 및 다른 도구의 역할 등록, 새 맥락 생성과 자동 호출 연결. 계획 검토자의 일반 설치·이동 시 링크 갱신 자동화.
- 분야별 병렬 검토 적용 조건과 결과 통합 방식.
- 작업 영향별 필수 검사·테스트, 완료 판정과 미해결 지적 처리 기준의 세부화.

## 3. 설치와 업데이트

목표는 Git clone 또는 다운로드로 같은 규칙 버전을 설치하는 것이다. 아래 항목은 구현 전 결정한다.

- 지원할 운영체제와 에이전트 도구, 도구별 지침 경로.
- 심볼릭 링크·파일 복사·참조 방식 중 환경에 맞는 설치 방법.
- 기존 파일 감지, 백업, 변경 미리보기, 제거 및 복구.
- 명시적 업데이트와 자동 동기화의 선택, 버전 고정 및 롤백.
- 설치된 규칙 버전과 원격 정본의 일치 여부 확인.

원격의 최신 내용을 매번 자동 적용하는 방식은 아직 확정하지 않았다.

## 4. 방법론 실험

후속 논의 후보이며 기본 동작으로 활성화하지 않는다.

- 독립적인 조사·구현·리뷰를 여러 에이전트에 나누는 방식.
- 병렬 작업 시 파일 소유권, 별도 worktree, 통합 담당자와 충돌 처리.
- 작업별 시간·비용·결과 품질을 비교해 병렬화 조건 결정.
- 새 방법론은 공식 자료 확인과 작은 실험을 거쳐 채택.

## 설치 CLI 계획

로컬 `.harness/plans/P01-installation-cli.md`와 하위 T01~T05에 초안을 작성한다. 계획은 로컬 제외 대상으로 공유 커밋에 포함하지 않는다. macOS CLI 구현과 임시 환경 자동 테스트를 진행했다. 릴리스 게시와 사용자 직접 다운로드 최종 테스트는 별도 단계다.

### macOS CLI 구현 상태

install/status/update/uninstall/init, 두 도구의 개인 지침·검토자 adapter, allowlist 패키징과 체크섬 다운로드를 구현했다. 실제 홈 설치는 수행하지 않았으며 임시 HOME에서 확인한다. 기본 역할 권한은 읽기 전용으로, RUN/ENV 실행 근거는 주 세션에 요청할 수 있다.

검증: 임시 환경 15개 자동 테스트와 독립 RUN 검토/재검토, 실제 홈 변경 미리보기 통과. HTTPS 실제 전송과 새 세션 역할 발견은 최종 설치 테스트로 남긴다.


### 2026-10-14 작업 구조·간소 경로 합의

- 정식 계획은 작업별 폴더와 내부 history로 보존하고 완료는 [done]- 접두사로 표시한다. S 계층에만 최상위 index를 둔다. 추가 상태 체계는 도입하지 않는다.
- 명확성·단일 구현 방향·제한 영향·검사 가능·복구 가능을 모두 만족하면 별도 계획/계획 리뷰 없이 간소 경로를 적용한다. 위험 불확실성에 따른 결과 리뷰와 정식 경로 전환 기준은 계획 거버넌스를 따른다.
- 간소 경로에 ID나 여러 메모리 파일을 강제하지 않는다. 기존 기록 자동 이동·전역 설치 갱신은 이번 변경에 포함하지 않는다.
